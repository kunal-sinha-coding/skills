# Repository Notes

## 2026-09-02: Create hill-climbing skill

Added `hill-climbing/SKILL.md` and its UI metadata to provide a controlled, iterative training-debugging workflow. The skill defaults to a stable ten-example evaluation batch, creates a timestamped dedicated branch, reads the repository’s documented command and log schema, classifies every failure, records root-cause analysis and one-fix experiments in `hillclimbing.txt`, and compares each subsequent run against the same task IDs. The skill was validated with the bundled skill validator.
Commit: Clarify hill-climbing Git synchronization

Updated hill-climbing/SKILL.md to explicitly require following repository AGENTS.md commit and push instructions, pushing the dedicated experiment branch after its first commit, and pushing subsequent related changes. Replaced the conflicting blanket no-push handoff guidance while preserving the prohibition on unrelated Git operations.

## 2026-09-02: Make pass rate the hill-climbing objective

Updated hill-climbing/SKILL.md so fixed-batch pass rate is the primary optimization, selection, and stopping metric. Reward and error buckets remain secondary diagnostics, and every before-and-after claim must compare pass rate on the identical task IDs and denominator.

## 2026-09-02: Clarify default and explicit branch workflow

Updated AGENTS.md so commits and pushes default to main, while an explicitly specified branch is used when provided. Synchronized the instruction across the three local repositories.

## 2026-09-02: Require keep or revert decisions

Updated hill-climbing/SKILL.md to require an explicit keep-or-revert decision and the reasoning for that decision at the end of every iteration, based primarily on fixed-batch pass rate.

## 2026-09-02: Require generalizable hill-climbing changes

Updated hill-climbing/SKILL.md to favor upstream changes likely to generalize beyond the tiny evaluation batch. Batch-specific, task-order-specific, and seed-only gains are now diagnostic evidence rather than valid improvements without independent confirmation or a clear general mechanism.

## 2026-09-02: Require renewed hypotheses before pausing

Updated hill-climbing/SKILL.md so an exhausted hypothesis list triggers a full review of prior results and error analyses, including meta-level reflection and new generalizable hypotheses, rather than pausing the session immediately.

## 2026-09-02: Require meta-review after every iteration

Updated hill-climbing/SKILL.md so every iteration includes a meta-level review of the full experiment history, not only sessions that have exhausted their current hypotheses.

## 2026-09-02: Broaden candidate intervention classes

Updated hill-climbing/SKILL.md to explicitly consider data processing, broad context engineering, training methods, reward alignment, generation algorithms, and answer review alongside prompt changes.

## 2026-09-02: Make intervention examples non-exhaustive

Clarified that the listed intervention classes are examples rather than an exhaustive set, and that any evidence-supported pipeline change may be considered.

## 2026-09-02: Require broad metric logging and inspection

Updated hill-climbing/SKILL.md to require logging and studying all relevant metrics for every training strategy. Loss, reward, completion behavior, learning-rate schedules, gradients, and evaluation metrics are examples rather than an exhaustive list.

## 2026-09-02: Prevent iteration summaries from ending the loop

Updated hill-climbing/SKILL.md to make iteration summaries internal progress updates, require immediate continuation into the next supported iteration, and require returning to the active loop after interruptions instead of sending a final handoff.

## 2026-09-02: Require discriminating meta-diagnostics

Updated hill-climbing/SKILL.md to require competing high-level explanations and small discriminating diagnostics during meta-analysis. The pass-at-N capability test is an example of distinguishing missing capability from insufficient exploration, not a mandatory diagnostic template.
